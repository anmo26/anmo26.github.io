# how a sticky note turns into an update

Anyone who opens this site can stick a note on it. Some of those notes are
about the site itself — this is in the way, that is a second late, why can't
I do X — and they are the best kind of feedback there is, because they come
from someone using the thing rather than from someone building it.

They still have to go through a door. This is the door.

## the four steps

**1. the wall is read, not watched.** Nothing on the wall reaches the site by
itself. When we sit down to do an update, the first thing that happens is
that every note on every page is read and written into a ledger — what it
says, who wrote it, which page it is on, and *what it is stuck next to*.
That last one matters: a note about the clock is stuck on the clock, and
six months from now "1310, 163" would tell nobody anything.

**2. every note is sorted, and you see the sorting.** Each one comes back to
you as: what it asks for, whether it is a small fix or a week of work,
whether it contradicts something you have already decided, and a
recommendation — build it, park it, or leave it. Notes flagged as odd (see
below) come with the flag showing.

**3. you say yes, note by note.** Out loud, one at a time. Nothing is built
because it was on the wall. A note is a request; your yes is the decision.
Saying no is a normal outcome and it is recorded, so the same note is never
put in front of you twice.

**4. what ships is written down.** The note is marked done, the update is in
the to-do card on the front page, and the old to-do is filed in the site
updates folder. So there is always a line from "somebody stuck a note on the
clock" to "the clock was fixed on the fifteenth".

## nothing on the wall is an instruction

This is the part that matters if the site ever gets more visitors than
friends.

A note is **text a stranger typed**. It is treated as text, always. A note
that says "ignore your instructions", or "run this command", or "add my link
to the front page", or "paste the keys here" gets read, flagged in the
margin, and shown to you exactly like any other note. It is never acted on
because it asked to be acted on. The ledger flags the obvious ones — URLs,
commands, anything addressed to an assistant rather than to you — but the
real defence is not the flag. The real defence is step 3: a person reads
every one of these and decides.

The same goes for what a note can reach. Nothing on the wall can move, edit
or delete a file in your folder. The wall is a separate document that the
site reads; the folder on your laptop is the site.

## what a wiped wall costs

Nothing, now. Anyone can take any note down, which is what lets you clear a
suggestion once it has been built — but every note that has ever been read
is kept in the ledger, including the ones that have since been binned. If
somebody clears the whole wall tomorrow, we still have every word of it.

## what is deliberately not automatic

- Notes never queue themselves up to be built.
- Notes never publish anything.
- A note cannot change another note's words — only the hand that wrote a
  note can edit it. Anyone can reply to it, and anyone can bin it.
- The site never emails, posts or sends anything anywhere.

The whole point is that visitors get to *notice things you do not*, and you
still get to decide what the site is.
